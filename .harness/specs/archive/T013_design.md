# T013 Technical Design

## 1. Objective
Implement a filesystem-backed legal document route using the App Router so each markdown file in `content/legal/` is addressable through `/legal/[slug]`, parsed on the server, and rendered with an RSC-compatible markdown renderer.

## 2. Scope
- Add the dynamic legal route.
- Add a small server-only content loader for legal documents.
- Add markdown parsing dependencies required for frontmatter and safe rendering.
- Align existing legal navigation links with the new route structure.

## 3. Files to Create or Modify
- **Create**: `src/app/legal/[slug]/page.tsx`
- **Create**: `src/lib/legal.ts`
- **Modify**: `src/app/components/Footer.tsx`
- **Modify**: `package.json`
- **Modify**: lockfile generated by pnpm after dependency changes

## 4. Design Details
### 4.1 Legal content loader
- Create `src/lib/legal.ts` as a server-side utility module.
- Define a typed `LegalDocumentMetadata` interface with `title`, `subtitle`, and `lastUpdated`.
- Define a typed `LegalDocument` return shape containing `slug`, `metadata`, and `content`.
- Implement a helper that resolves the absolute path to `content/legal/` using `path.join(process.cwd(), "content", "legal")`.
- Implement an async function to list all `.md` files from `content/legal/` and convert filenames into slugs.
- Implement an async function to read `content/legal/[slug].md` with `fs/promises`.
- Parse the file content with `gray-matter` and return the frontmatter plus markdown body.
- Treat missing files as a null result or explicit not-found signal so the route layer can call `notFound()`.

### 4.2 Dynamic route page
- Implement `src/app/legal/[slug]/page.tsx` as a Server Component only.
- Read `params.slug`, load the matching document through `src/lib/legal.ts`, and call `notFound()` if the document does not exist.
- Render the markdown body using an RSC-safe renderer such as `react-markdown` rather than raw HTML injection.
- Export `generateStaticParams()` so known markdown files are statically generated from the filesystem source of truth.
- Keep the first version minimal and focused on content rendering; visual refinement belongs to T014.

### 4.3 Navigation alignment
- Update `src/app/components/Footer.tsx` so legal links target `/legal/privacy-policy` and `/legal/legal-notice`.
- Preserve the existing footer structure and styling unless a change is required for route correctness.

### 4.4 Dependencies
- Add `gray-matter` for frontmatter parsing.
- Add `react-markdown` for markdown rendering in a Server Component.

## 5. Implementation Notes
- Avoid custom markdown-to-HTML conversion because the blueprint explicitly discourages unsafe HTML rendering.
- Keep legal document loading centralized in `src/lib/legal.ts` so T014 can focus only on presentation concerns.
- If metadata fields are missing in a document, the loader should still return a stable typed object, with field handling decided in the page component.

## 6. Validation Plan
- Run `pnpm lint && pnpm typecheck`.
- Run `pnpm build`.
- Manually verify `/legal/privacy-policy` and `/legal/legal-notice` render.
- Manually verify an invalid route such as `/legal/unknown` resolves to 404.
