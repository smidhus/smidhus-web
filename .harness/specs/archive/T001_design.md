# T001 Technical Design

## 1. Design Summary
T001 is a greenfield bootstrap task. The repository currently contains only harness metadata, so execution should first scaffold the base Next.js application, then apply the brand tokens, root typography, and security configuration required by the blueprint and task description.

## 2. Implementation Scope
- Initialize a new Next.js project in the repository root using `pnpm`, TypeScript, Tailwind CSS, and the App Router.
- Keep the generated structure under `src/` so future tasks can place shared components in `src/app/components` and route views in `src/app`.
- Configure Tailwind theme extensions for the four Smidhus base colors.
- Load `Fira Code` and `Inter` from `next/font/google` in the root layout and expose them through body/class composition or CSS variables.
- Configure the required HTTP response headers in `next.config.js`.
- Ensure the default starter content compiles cleanly and does not introduce validation warnings.

## 3. Files To Create Or Modify
- `package.json`: Create via project scaffold; must use scripts compatible with `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`.
- `pnpm-lock.yaml`: Create from dependency installation.
- `tsconfig.json`: Create via scaffold with strict TypeScript-compatible settings.
- `next.config.js`: Create or modify to define the required security headers.
- `postcss.config.js`: Create via scaffold for Tailwind processing.
- `tailwind.config.ts`: Create or modify to expose the Smidhus color palette through theme extension.
- `src/app/layout.tsx`: Create or modify to load `Fira Code` and `Inter` with `next/font/google` and apply them globally.
- `src/app/page.tsx`: Create via scaffold; keep starter content minimal and compatible with future tasks.
- `src/app/globals.css`: Create or modify for baseline Tailwind layers and optional font utility mapping.
- `eslint` configuration file generated by the scaffold: Keep or adjust only if required for a warning-free lint result.
- Test configuration and placeholder test files: Create only as needed so `pnpm test` succeeds consistently.

## 4. Execution Notes
- Prefer the standard Next.js scaffold to avoid hand-assembling framework files.
- If the current Next.js version emits `next.config.ts` by default, normalize to `next.config.js` only if needed to satisfy the task wording without reducing maintainability.
- Keep typography wiring simple: define font variables or classes in `layout.tsx`, then leave finer-grained usage to later UI tasks.
- Do not implement Navbar, Footer, hero layout, or interactive buttons in this task; those belong to T002-T005.

## 5. Validation Requirements
- Run `pnpm lint && pnpm typecheck`.
- Run `pnpm test`.
- Run `pnpm build`.
- Resolve any generated scaffold warnings so the repository is left in a clean baseline state.

## 6. Required Technical Profiles
- `builder`: Required to scaffold the application, implement configuration changes, and run the validation pipeline.
